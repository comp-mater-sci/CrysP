\hypertarget{page_conventions_conventions}{}\doxysection{VEF common notation conventions}\label{page_conventions_conventions}
This section describes the notation conventions commonly used throughout the VEF software.\hypertarget{page_conventions_convention_physicalquantities}{}\doxysubsection{Physical quantities}\label{page_conventions_convention_physicalquantities}
The manual generally adheres to the scientific notation of physical quantities that is commonly used in the field of mechanics. More specifically, the following conventions are followed\+:


\begin{DoxyItemize}
\item Tensors are denoted with capitalized boldface Latin letters, or with boldface Greek letters.

\textbackslash{}egs $ \mathbf{S} $ is deviatoric stress, $ \mathbf{A} $ is deviatoric strain rate mode, $ \boldsymbol\sigma $ is the total stress and $ \boldsymbol\epsilon $ the plastic strain.
\item Vectors are denoted with lowercase boldface Latin letters.

\textbackslash{}eg $ \mathbf{n} $ is a plane normal vector.
\item Scalars, including tensor components and vector components, are denoted with lower-\/ or uppercase, Latin or Greek letters. They are never boldface.

\textbackslash{}egs $ W $ is plastic work, $ \sigma_h $ is the hydrostatic stress and $ \sigma_{13} $ is a component of tensor $ \boldsymbol\sigma $. ~\newline

\end{DoxyItemize}

Exceptions from these rules are clearly indicated where appropriate.

Note that strain tensors (and derived quantities) mentioned in the VEF are the {\bfseries{plastic strains}} unless stated otherwise. Likewise, the stresses calculated and reported by the VEF are usually the {\bfseries{deviatoric stresses}}.\hypertarget{page_conventions_autotoc_md32}{}\doxysubsubsection{Naming of physical quantities in input and output files}\label{page_conventions_autotoc_md32}
Different conventions apply to physical quantities in input and output files\+:


\begin{DoxyItemize}
\item The typesetting decorations (boldface etc.) are obviously dropped.
\item Greek letters are replaced by their full names or abbreviations.

\textbackslash{}egs {\ttfamily sigma}, {\ttfamily rho} and {\ttfamily eps}
\item One or more indices are preceded by underscore symbol ({\ttfamily \+\_\+}).

\textbackslash{}eg {\ttfamily eps\+\_\+11}
\end{DoxyItemize}\hypertarget{page_conventions_convention_reference_frame}{}\doxysubsection{Reference frames}\label{page_conventions_convention_reference_frame}
The VEF uses two different reference frames in the physical, 3-\/dimensional space\+:


\begin{DoxyEnumerate}
\item {\bfseries{The material reference frame}}\+: the reference frame in which the material data, such as crystallographic texture, are given. This frame can be considered as the global reference frame.

To denote the components of second-\/order tensors in the material reference frame, numeral indices are used. Repeated axes can be omitted.

\textbackslash{}egs $ \sigma_{11} $, $ D_{22} $, $ S_{13} $. ~\newline

\item {\bfseries{The sample reference frame}}\+: a local reference frame that is attached to the virtual sample

Components of second-\/order tensors in the sample reference frame are indicated by ~\newline
 using the (lowercase) letters $x$, $y$ and $z$ to denote the axes. Repeated axes can be omitted.

\textbackslash{}egs $ \sigma_x $ (or equivalent\+: $ \sigma_{xx} $), $ D_y $, $ S_{xz} $
\end{DoxyEnumerate}

Both material and sample reference frames do not change during a simulation and are fixed in space.\hypertarget{page_conventions_convention_indexnotation}{}\doxysubsection{Index notation}\label{page_conventions_convention_indexnotation}
Apart from the notation related to the reference frames (cf. \mbox{\hyperlink{page_conventions_convention_reference_frame}{above}}), the VEF also uses other indices. These usually indicate\+:
\begin{DoxyItemize}
\item Arbitrary 2-\/dimensional sections of stress space or strain rate space

The {\bfseries{section reference frame}} is defined by two arbitrary axes within the 6-\/dimensional stress space. The two axes defining the section are generally denoted by the (capitalized) letters $ X $ and $ Y $.

\textbackslash{}egs $ \sigma_X $ and $ \sigma_Y $
\item A direction that characterizes a specific sample

\textbackslash{}eg $ S_0 $ for stress in sample at 0 degrees
\item Equivalent quantities

\textbackslash{}eg $ \epsilon_{vM} $ is the Von Mises equivalent plastic strain
\item Slip system-\/specific quantitites (usually denoted by index $ s $)

\textbackslash{}eg $ \dot\gamma_s $ is the slip rate on slip system $ s $

\hypertarget{page_conventions_convention_configuration}{}\doxysubsection{Configuration options and configuration fields}\label{page_conventions_convention_configuration}
The \mbox{\hyperlink{page_expert_mode}{VEF expert mode}} makes use of configuration files, containing configuration fields that are grouped in configuration options (their exact definition is given in \mbox{\hyperlink{page_alamdmc_format_alamdmc_format_configoptions}{Configuration Options}}). Some conventions are defined in order to facilitate readability of the documentation concerned\+:


\begin{DoxyItemize}
\item Configuration field names are typeset with bold typewriter font.

\textbackslash{}eg \textbackslash{}conffield\+\_\+typeset\{example\+\_\+field\} is a field name
\item A declaration of a configuration field (or\+: field declaration) always involves giving its \mbox{[}type\mbox{]} (\mbox{\hyperlink{page_alamdmc_format_field_type}{field\+\_\+type}}). By convention, the type of the field is embraced within parentheses.

\textbackslash{}eg The declaration \textbackslash{}confdef\{example\+\_\+field,string\} declares a field of type {\ttfamily string}
\item A configuration option consists of one or more fields. Field declarations that are merely separated by spacing in the documentation, belong to the same configuration option\+: they need to be provided on a single line of configuration file, and in the same order.

\begin{DoxyParagraph}{\quad{} Example\+: }
\textbackslash{}confdef\{field1,integer\} \textbackslash{}confdef\{field2,real\} is a configuration option consisting of two fields, the first of type {\ttfamily integer}, and the second of type {\ttfamily real}.~\newline
 An example of the corresponding line in the configuration file might be\+: 
\begin{DoxyCode}{0}
\DoxyCodeLine{1 0.7}

\end{DoxyCode}
 ~\newline

\end{DoxyParagraph}

\item The consecutive configuration options that belong to a specific part of the configuration file, are enumerated in the documentation. Note that numbering may restart for a following section of configuration file.

\begin{DoxyParagraph}{Example\+:}
A configuration file section may be documented as follows\+: ~\newline

\begin{DoxyEnumerate}
\item \textbackslash{}confdef\{option1field,integer\} is a first option (consisting of a single field).
\item \textbackslash{}confdef\{option2field1,real\} \textbackslash{}confdef\{option2field2,real\} is a second (consecutive) option (consisting of two fields).
\end{DoxyEnumerate}
\end{DoxyParagraph}

\item Mandatory configuration options are always numbered as\+: 1. ,2. , 3. etc. If a configuration option has a limited number of supported values, those values may be given in an unenumerated and indented list. Value-\/dependent suboptions that depend on the value of previous field, are documented as a letter-\/numerated list (a., b., c., etc.), and they are indented accordingly. Second-\/level suboptions (sub-\/suboptions) are listed as a Roman-\/numerated list (i., ii., iii., etc.) with further indentation.

\begin{DoxyParagraph}{\quad{} Example\+: }
A configuration file section may be documented as follows\+:
\begin{DoxyEnumerate}
\item \textbackslash{}confdef\{op1f,integer\} is mandatory; it has no value-\/dependent suboptions.
\item \textbackslash{}confdef\{op2f,string\} is mandatory. The field \textbackslash{}conffield\+\_\+typeset\{op2f\} has 3 supported values\+: {\ttfamily xx}, {\ttfamily yy}, and {\ttfamily zz}.
\begin{DoxyItemize}
\item {\ttfamily xx}~\newline
 If \textbackslash{}conffield\{op2f\}={\ttfamily xx}, there are two value-\/dependent suboptions\+:
\begin{DoxyEnumerate}
\item \textbackslash{}confdef\{xx\+\_\+subop2af,real\} ...
\item \textbackslash{}confdef\{xx\+\_\+subop2bf,logical\} ...
\begin{DoxyItemize}
\item {\ttfamily True}~\newline
 ...
\item {\ttfamily False}~\newline
 requires 2 sub-\/suboptions\+:
\begin{DoxyEnumerate}
\item \textbackslash{}confdef\{xx\+\_\+false\+\_\+subsubop2bif,path\} ...
\item \textbackslash{}confdef\{xx\+\_\+false\+\_\+subsubop2biif,real\} ...
\end{DoxyEnumerate}
\end{DoxyItemize}
\end{DoxyEnumerate}
\item {\ttfamily yy}~\newline
 If \textbackslash{}conffield\{op2f\}={\ttfamily yy}, there are no suboptions.
\item {\ttfamily zz}~\newline
 If \textbackslash{}conffield\{op2f\}={\ttfamily zz}, there is one value-\/dependent suboption\+:
\begin{DoxyEnumerate}
\item \textbackslash{}confdef\{zz\+\_\+subop2af,integer\} ...
\end{DoxyEnumerate}
\end{DoxyItemize}
\item \textbackslash{}confdef\{op3f,real\} is mandatory; it has no value-\/dependent suboptions. 
\end{DoxyEnumerate}
\end{DoxyParagraph}
