The Alam\+DMC configuration file (.cfg) has to follow some basic formatting rules. Some dedicated formats for a number of special configuration options may also apply.\hypertarget{page_alamdmc_format_alamdmc_format_basics}{}\doxysection{Basic Formatting rules}\label{page_alamdmc_format_alamdmc_format_basics}
\label{page_alamdmc_format_desc_alamdmc_format}%
\Hypertarget{page_alamdmc_format_desc_alamdmc_format}%
Configuration files of the {\ttfamily alam\+DMC} program have a fixed format. The files are read and interpreted by the program according to Fortran formatted input rules, which implies that\+:
\begin{DoxyItemize}
\item the files are processed line by line,
\item empty lines are typically interpreted as containing \textquotesingle{}zero\textquotesingle{} of the type being read,
\item tabulators are not allowed as blank characters.
\end{DoxyItemize}

\begin{DoxyAttention}{Attention}
Please make sure that Alam\+DMC configuration files do not contain tabulators.
\end{DoxyAttention}
\label{page_alamdmc_format_desc_alamdmc_comments}%
\Hypertarget{page_alamdmc_format_desc_alamdmc_comments}%
Additionally, the configuration files can include comments that are ignored by the program. A comment starts with {\ttfamily \#} and spans till the end of the line. A comment may start at the beginning of the line or after a data field. \begin{DoxyParagraph}{Example\+:}

\begin{DoxyCode}{0}
\DoxyCodeLine{\textcolor{preprocessor}{\# This is a comment}}
\DoxyCodeLine{6           \# This is a comment that follows a data field.}
\DoxyCodeLine{ \# Beware, \textcolor{keyword}{this} comment begins at 2nd character, so \textcolor{keyword}{this} line contains (empty) data!}

\end{DoxyCode}

\end{DoxyParagraph}
\begin{DoxyNote}{Note}
If a comment does not start at the first position in a line, the line is interpreted as containing a data field.
\end{DoxyNote}
\begin{DoxyAttention}{Attention}
Comment lines are {\itshape not allowed} if they break \mbox{[}compound data\mbox{]} (\mbox{\hyperlink{page_alamdmc_format_compound}{compound}}) across two or more lines. An example is given \mbox{[}here\mbox{]} (\mbox{\hyperlink{page_alamdmc_format_option_discrete}{option\+\_\+discrete}}).
\end{DoxyAttention}
Generally, the user is supposed to provide correct configuration files. Although the program attempts some rudimentary detection of errors and mistakes in the configuration file, the user is advised not to rely on that feature.\hypertarget{page_alamdmc_format_alamdmc_format_structure}{}\doxysection{Configuration File Structure}\label{page_alamdmc_format_alamdmc_format_structure}

Any line in the configuration file that is not a comment line, belongs to a {\itshape configuration option}. A configuration option consists of one or more {\itshape configuration fields}. Each configuration field has a certain {\itshape type}\label{page_alamdmc_format_field_type}%
\Hypertarget{page_alamdmc_format_field_type}%
, which can be
\begin{DoxyItemize}
\item trivial data types ({\ttfamily path}, {\ttfamily string}, {\ttfamily logical}, {\ttfamily integer} or {\ttfamily real}), or
\item compound data types\label{page_alamdmc_format_compound}%
\Hypertarget{page_alamdmc_format_compound}%

\end{DoxyItemize}

There are \mbox{[}specific notation conventions\mbox{]} (\mbox{\hyperlink{page_conventions_convention_configuration}{Configuration options and configuration fields}}) for configuration options, fields and field declarations.

Any configuration option belongs to one of the two groups\+:
\begin{DoxyEnumerate}
\item {\itshape single-\/line options}\+: such options always occupy exactly one line in the configuration file. One or more fields per line is allowed.
\item {\itshape multi-\/line options}\+: depending on the values of the fields in the first line, {\bfseries{zero or more}} subsequent lines may follow. As in the case of the single-\/line options, any line may contain one or more fields.
\end{DoxyEnumerate}

\item \label{page_alamdmc_format_option_doublebiased}%

{\ttfamily doublebiased}~\newline
 A range of non-\/uniformly distributed points, with the density either higher or lower at the endpoints. The double-\/biased range gives basically a sequence of points that would result from two \mbox{\hyperlink{page_alamdmc_format_option_biased}{biased ranges}} stitched together, with the stitching point located at the half point of the interval \mbox{[}\textbackslash{}conffield\{range\+\_\+begin\},\textbackslash{}conffield\{range\+\_\+end\}\mbox{]} and the \textbackslash{}conffield\{ratio,biased\+\_\+ratio\} of the second range being the reciprocal of the \textbackslash{}conffield\{ratio,biased\+\_\+ratio\} in the first range.
\begin{DoxyEnumerate}
\item \textbackslash{}confdef\{range\+\_\+begin,real,doublebiased\+\_\+range\+\_\+begin\} \textbackslash{}confdef\{range\+\_\+end,real,doublebiased\+\_\+range\+\_\+end\} \textbackslash{}confdef\{ratio,real,doublebiased\+\_\+ratio\} has identical meaning of the first two fields as in the {\ttfamily uniform} range. \hypertarget{page_alamdmc_format_incrementation_option}{}\doxysubsection{Configuration options for strain incrementation}\label{page_alamdmc_format_incrementation_option}
The VEF provides several ways to control how the deformation is incremented if strain evolution of the material is analyzed, as follows\+:


\begin{DoxyEnumerate}
\item \textbackslash{}confdef\{incrementation\+\_\+type,string\} specifies how the strain increments will be calculated. If the option takes the value\+:
\begin{DoxyItemize}
\item {\ttfamily Strain\+Tensor}\+: the strain increment tensor $ \Delta\boldsymbol{\epsilon} $ satisfies $ \| \boldsymbol{\epsilon} + \Delta\boldsymbol{\epsilon} \| - \| \boldsymbol{\epsilon} \| $ = \textbackslash{}conffield\{increment\+\_\+magnitude\}.
\item {\ttfamily Strain\+Tensor\+Increment}, the strain increment tensor $ \Delta\boldsymbol{\epsilon} $ satisfies $ \| \Delta\boldsymbol{\epsilon} \| $ = \textbackslash{}conffield\{increment\+\_\+magnitude\}.
\item {\ttfamily Strain\+Tensor\+Component}, the strain increment tensor $ \Delta\boldsymbol{\epsilon} $ is such that its normal component along the sample x-\/axis $ \Delta \epsilon_{xx} = $ \textbackslash{}conffield\{increment\+\_\+magnitude\}.
\item {\ttfamily Plastic\+Work}, the plastic work per increment $ \Delta W = $ \textbackslash{}conffield\{increment\+\_\+magnitude\}. \begin{DoxyNote}{Note}
Some values for \textbackslash{}conffield\{incrementation\+\_\+type\} are only allowed in particular modules of the VEF.
\end{DoxyNote}

\end{DoxyItemize}
\item \textbackslash{}confdef\{step\+\_\+magnitude,real\} provides maximal deformation (as specified by \textbackslash{}conffield\{incrementation\+\_\+type\}) to be reached in a given deformation step. If the module allows simulating only one step (i.\+e. one stress path) this field also provides total magnitude to be reached. ~\newline

\item \textbackslash{}confdef\{increment\+\_\+magnitude,real\} sets the magnitude of deformation increments. Note that the last increment may have a slightly different magnitude than specified in order to reach exactly \textbackslash{}conffield\{step\+\_\+magnitude\}.
\end{DoxyEnumerate}
